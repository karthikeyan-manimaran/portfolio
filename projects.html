// SAC vs DDPG Comparison
  • SAC — entropy-regularized, superior exploration, more stable on continuous action spaces
  • DDPG — deterministic policy, faster convergence in constrained scenarios
  • Head-to-head benchmark on identical reward structures
  • SAC outperformed DDPG on sample efficiency and final landing precision
// Reward Engineering
  • Proximity — inverse distance to pad, shaped to avoid local minima
  • Velocity damping — penalizes high speed near target for smooth descent
  • Alignment error — penalizes yaw offset from target orientation
  • Crash penalty — hard negative on collision or out-of-bounds
// Sim-to-Real Path
  • Trained policy in Gazebo with PX4 SITL
  • Domain randomization: wind disturbance + pad position noise
  • MAVROS topics identical to real hardware — same ROS 2 interface
  • Physical testing ongoing in VIT indoor arena (see Project 02)
  • ArUco marker detection for real-world pad tracking
// Docker Compose Setup
  • 3 isolated containers orchestrated via Docker Compose
  • One command trains the full pipeline: docker compose up
  • Reproducible across any Linux x86 machine
  • Shared volumes for model checkpoints and training logs

// Stage 1 — Dynamic Masking
  • YOLO identifies dynamic object classes (person, car, bicycle, truck…)
  • Mask R-CNN produces pixel-level instance segmentation masks
  • All dynamic pixels zeroed before feature extraction
  • Residual frame contains only static scene structure
// Stage 2 — SuperGlue Matching
  • SuperPoint keypoints extracted from masked frames only
  • SuperGlue GNN-based matching — robust in low-texture environments
  • Handles large viewpoint changes between frames
  • RANSAC geometric verification removes outlier matches
// Stage 3 — Pose Recovery
  • Essential-matrix decomposition → relative R, t per frame pair
  • Monocular depth estimation provides scale approximation
  • Trajectory accumulated frame-by-frame for full 6-DoF path
  • Evaluated on KITTI dynamic sequences (seq 05, 09, 10)
// Results vs Baseline
  • Measurable drift reduction vs vanilla ORB-SLAM2 on dynamic KITTI seqs
  • ORB-SLAM2 corrupted by movers → large trajectory jumps
  • Masked pipeline maintains coherent trajectory through dynamic regions
  • Deployed as fallback odometry when GPS + stereo depth fail on-drone
USE CASE // Secondary odometry source on the UAV stack — when GPS drops and RealSense stereo fails (reflective/featureless surfaces), the monocular pipeline keeps the MAVROS position lock alive.

// 3 Tool Specs
  • search_docs — FAISS vector index over IPL 2023 & 2024 PDFs, TF-IDF+LSA 256-dim embeddings, top-3 chunks
  • query_data — Pandas aggregations over match CSVs (scorers, H2H, team stats)
  • web_search — Tavily API for live results on news not in training data
// Safety Mechanisms
  • Hard 8-step cap — enforced in the loop, no runaway agents
  • Loop detection — flags same (tool, input) repeated 3× in window
  • Refusal handling — off-topic questions cleanly refused
  • Structured JSON trace — every step logged: tool, input, result, reason, duration
// Multi-Tool Trace Example

// Design Philosophy
  • No LangChain AgentExecutor — explicit while loop, every step debuggable
  • Interview-explainable — clean, modular, type-hinted core loop
  • Tools chain sequentially: search_docs → query_data → final_answer
  • Standardized output with citations & retrieval tracing
